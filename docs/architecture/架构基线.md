# Synech v1 架构基线

> 状态：未发布 v1 目标基线
> 适用范围：Windows、本地单用户、运行时强制单 Product Home / 单 PanelHost、仅 loopback API

本文是 Synech 稳定概念、所有权和工程门禁的最高事实源。[开发维护规则](开发维护规则.md) 负责把这些事实转成日常开发纪律。Handbook 负责解释实现；实现、测试或 Handbook 与本文冲突时，必须在同一变更中完成收口，不能长期保留双重事实。

## 1. 产品与领域事实

| 概念 | 定义 | 权威 owner | 不拥有 |
| --- | --- | --- | --- |
| Space | 通用长期组织空间 | SpaceFeature | Workspace mount、外部文件内容、Knowledge 内容 |
| Workspace | 真实目录的稳定登记身份 | WorkspaceFeature | 目录内用户文件、Space membership |
| Knowledge | 长期沉淀的 Note/Page/Theme/Link | PersonalKnowledgeFeature | Space 生命周期、外部来源 |
| Conversation | 固定归属一个 Space 的对话 | Ordinary | 浏览页面、临时 cwd、Workspace 资源身份 |
| SpaceReferenceItem | Space 对外部或托管资源的一次 membership | SpaceFeature | 被引用对象自身生命周期 |
| Memory | 按 global/Space owner 隔离的历史认识、会话总结、可选长期内容、来源和检索投影 | MemoryFeature | 原始 Conversation、owner 身份、Workspace 文件资源 |
| CollaborationRules | 用户明确维护的全局、Space 规则，以及外部 Workspace 的 AGENTS.md 资源规则 | CollaborationRulesFeature | Memory、Knowledge、原始对话、外部 Workspace 文件内容 |

稳定规则：

- Space reference 直接保存 `workspaceId`；关系身份是 `SpaceReferenceItem.id`，不存在第二套 WorkspaceLink。
- Workspace owns `workspaceId + mountVersion + sourceIdentity + status + visibility`。Workspace 不再作为 Panel 的独立产品入口；本地目录的添加、展示和重连通过 Space reference 入口完成。
- 退役的独立 `/api/workspaces` surface 不得继续创建、列出、隐藏、删除或重连 Workspace；当前实现使用 Space 作用域的本地资源入口。WorkspaceFeature 仍是目录身份、mount 和文件生命周期的唯一 owner。
- Knowledge Note 的 `spaceId` 是可选组织关系；Space 删除只解除关系，不删除 Knowledge-owned 内容。
- Conversation owner 创建后不可改变且只能是 Space；上下文附件、Workspace 本地资源和 cwd 不能改变 owner。
- 外部用户文件默认不由 Synech 删除；managed content 必须走 owner 的 durable deletion lifecycle。
- CollaborationRules 的全局与 Space 文本位于 Product Home 的 `data/memory/collaboration-rules`；Workspace 规则以已登记 Workspace 根目录的 `AGENTS.md` 为唯一事实源，不复制为内部文件。规则写入必须复用 owner admission、来源身份与共享 mutation lock，并在锁内重新验证 `mountVersion`、`sourceIdentity` 和预期内容版本（CAS）；Workspace 登记删除不得删除外部 `AGENTS.md`。根文件缺席表示未设置，不做嵌套继承。规则是指导而非文件权限；Skills 来源与行为保持不变。
- Memory 是历史认识，只按 global/Space owner 隔离；Workspace 不再是长期记忆 owner。全局仅有一个默认关闭的 `enabled` 开关和管理范围，不保存 global 长期文档、不跨项目自动学习。关闭时阻断采集、整理结果发布、查询与背景供给，存储保留。

## 2. 分层和依赖

```text
Panel UI -> Panel API DTO / 明确的 ui-read-model facade
Panel Route -> Feature command 或 WorkbenchCoordination command
WorkbenchCoordination -> Feature contracts
Feature -> 自己的 Repository port
Repository adapter -> SQLite / filesystem
```

- `spaces`、`workspaces`、`personal-knowledge` 不得彼此直接依赖。
- 跨 Feature use case 由 `app/workbench-coordination` 拥有。
- Coordinator 不依赖具体 Repository、SQLite、HTTP 或 React。
- Route 不创建 Feature、不访问 Repository、不直接组合两个 Feature command。
- PanelHost 是进程组合根，不是供任意调用点读取内部对象的 service locator。
- Panel UI 不直接导入 `panel-api/read-model`；只允许 Panel API DTO 和明确审查为 client-safe 的 `ui-read-model` facade。

### Memory 入口边界

- `app/memory/index.ts` 是稳定产品 contracts/facade 入口；`app/memory/composition.ts` 是宿主组合根的 factory 装配入口。业务 Route/UI 不得通过装配入口访问内部 Repository 或整理实现；UI 仍遵守 Panel API DTO / `ui-read-model` 边界。
- 内部职责、共享预算、事务和最终供给核验的维护约束见 [开发维护规则：Memory 内部维护边界](开发维护规则.md#memory-内部维护边界)。Memory 的长期 owner 只有 global/Space；Workspace 只作为本地文件资源和外部规则来源，不引入第二套运行时。
- [ADR 0019](adr/0019-autonomous-memory-and-provenance.md)：轻量条目及不可变修订由现有 MemoryDocumentRepository 单事务发布，MemoryOwnerDoc 是无独立编辑权的概览；`updateMemory` 明确 entryId、修订种类、head CAS 与 requestId 幂等。普通来源会话删除保留已发布认识、删除原文索引及辅助 summary、source 标记为 deleted；分支替换按来源区间标记 superseded，涉及该来源的修订暂停当前供给并保留历史，不猜反证。`clear`/owner delete 仍清理内容并防回填。概览普通更新不换绑，纠正/撤回撤销受影响旧供给，来源状态每次动态复核。当前使用 FTS5/BM25 与主题/一跳关联，无向量依赖和查询时第二 Agent；未来索引增强只作同一内容的可重建投影。条目、查询、后台和 UI 在同一变更中接入并同步目标数据基线。

### Agent 运行层边界

- pi-agent 是 Agent Runtime Provider，负责通用运行机制；Synech 负责产品运行语义、权限、审批、账本、取消、恢复和呈现。
- 产品层只能依赖 Synech 自己的 Agent Runtime Port；现有 `AgentLoop`、ToolCenter 和 Ordinary execution port 是该边界的既有基础，不得默认新建并行完整 Runtime。产品层不得直接依赖 pi 的 `AgentHarness`、`AgentLane`、`Session`、`Context`、事件类型或内部 ID。
- Pi Adapter 是 pi 类型的唯一接入边界。pi 的 `entryId`、`tipId`、`operationId`、lane、branch 和 usageId 只属于 Adapter 内部事实，不是 Synech 产品稳定身份。
- Synech 产品身份使用 `conversationId`、`runId`、`turnId`、`toolInvocationId` 和 `checkpointId`；Adapter 可以提供不透明的 runtime checkpoint 映射，但产品层不得解析它。
- Pi transcript、Synech Run Ledger 和 Synech Product Projection 是三类不同事实，各自只有一个 owner；不得为了兼容而复制三份完整 transcript。
- Run 冻结执行所需模型配置与能力契约，不保存 Logo、其他模型配置或第二份 capabilityResolution。`birth.json` 一次保存不变事实（所选模型仅一份），`snapshot.json` 只提交动态状态和 revision；由同一 Ordinary Repository 还原公共文档。旧全量开发快照只通过显式 `compact:run-storage` 备份后转换，启动不兼容或静默改写（ADR 0015、0016）。
- 详细工具统计默认不采集；只有用户进入开发者模式并明确启用「记录详细工具统计」，新 Run 才冻结 `recordToolMetrics=true` 并记录。计费 usage、工具结果、审批和权限事实不是诊断统计，继续保存（ADR 0016）。
- Pi Adapter 允许 Host 启用最多 4 个、闲置 60 秒的原生 Session 句柄复用；每个 Session 的 access gate 与每个 writer 的世代栅栏保持权威。文件身份/修改信息变化、容量淘汰、删除和 Host shutdown 必须关闭旧句柄；禁止新增 transcript/runtime owner。分支命令返回值直接用于 UI，重复历史活动按 immutable Run 缓存复用；列表使用轻量 summary query，manifest 全量修复只属于恢复入口（ADR 0016）。
- 历史消息重新编辑与版本切换共用 Ordinary 会话锁、终态结算门禁和 Pi checkpoint。旧分支保留原始 transcript；Conversation control 只持有退休 Run 身份、上一次分支 tip 和临时切换意图，不复制 Pi 的分支树。Memory 的旧分支派生内容由 WorkbenchCoordination 生命周期入口失效；新采集排除保留的历史前缀，不能把旧授权排除区间重新回填（ADR 0015）。消息交互只提供编辑与版本选择，不提供独立回退或撤销/重做命令（ADR 0017）。
- pi 的 commit queue 只负责上游写入串行，不能替代 Synech 的世代栅栏。撤销某个写入世代后，该世代未完成的写请求不得继续写入。
- 工具的 live `ToolExecutionResult` 显式携带 `modelAttachments`，业务 `output` 不隐藏图片载体。文字留存只变换 `output`；模型适配出口投影为 durable `ToolCallResult`，Run/Panel 只保留图片引用，图片字节仍由 Pi Session 唯一持久化（ADR 0012）。
- 本次模型先确定，再一起冻结模型能力与工具目录；不能在生成目录后单独替换模型。`ViewImage` 读取授权工作区图片，`AttachmentReadImage` 读取选定附件，两者共享图片输入政策，文件权限分别沿既有入口验证（ADR 0014）。
- 删除 Run 证据前必须完成其 Session finalization 和已接受结果结算；失败时保留对应 Run、附件和会话供原入口重试。图片恢复同时核验 Pi 活动 transcript 与所属工具批次的 pending entry，不重执行工具或另存图片（ADR 0014）。
- Ordinary 的驻留 Run 集合同时服务对话可见性、轮次和提交幂等，不是可被统计或 Memory 读取驱逐的显示缓存；只能释放可重建的 activity projection。Session 重复删除时，已不存在视为完成，其余身份、元数据和活动 writer 错误仍上抛（ADR 0014）。
- Managed upload 在 Run birth 发布前先归属 Conversation；进程若在两步之间退出，只要 Conversation 未删除，启动恢复不得把这份上传当作孤儿删除，后续提交或 Conversation cleanup 再收敛它（ADR 0014）。
- 工具输入用途由显式契约决定，不按任意 `url/method` 字段猜测网络行为。懒连接 MCP 在每个连接世代读取真实目录，执行前比较所选工具的冻结 schema 和副作用契约；变化后拒绝执行，不在运行中替换授权事实（ADR 0013）。
- 详细设计和迁移规约见 [Agent 运行层接入与开发手册](Agent运行层接入与开发手册.md)；冻结决策见 `adr/0003-agent-runtime-provider-boundary.md`。

### 模型事实与模型接入边界

- 自动模型能力事实只读 pi-ai 真实 catalog，不维护手写模型定义表或构建期镜像。原生连接和显式目录作用域精确匹配；自定义连接自动匹配（完整 ID 优先，其次从左逐段去除 `/` 分隔前缀，优先最长的剩余精确 ID，保留目录 ID 内的命名空间；原厂来源优先，实质冲突不取第一条）。不根据 Base URL 猜 Provider，不剥离版本或型号后缀，不提供用户选择标准模型的入口。
- 远程 `/models` 只负责发现当前连接暴露的模型 ID，不是能力事实源；其持久化结果只能是发现缓存，不得携带或改写能力字段。
- 模型目录事实保持二态：`ConfirmedModelFacts`（逐字段真实投影）或 `UnconfirmedModelFacts`（仅 `status` 与 `modelId`）。ConfigCenter owns 每个连接下以原始模型 ID 为键的 `modelSettings`，仅保存稀疏用户设置，不复制目录默认值。有效能力使用用户设置优先于 Pi 默认的同一解析口径；未确认且未填写的上下文窗口统一使用产品运行预算 256,000 tokens（256K），不标为 Pi 确认事实。未知输出上限、视觉和推理能力不猜测；用户可在高级设置中配置。
- 模型身份、上游请求 ID 与连接 transport 分离：自定义兼容连接始终使用用户选择的协议，模型关联不得更换地址、凭据、请求 ID 或接口；仅复用同 transport 的 Pi compat/推理编码。原生连接继续使用 Pi 真实 stream/auth/filter/refresh，用户设置不改变原生模型身份。
- 用户输出上限始终可选。已知模型沿用 Pi 默认；未知 Anthropic-compatible 模型未填写时使用 4,096 tokens 请求预算以满足协议必填字段，不把它记作模型已确认的能力上限；未知 OpenAI-compatible 模型保持协议省略政策（ADR 0014）。
- 产品推理选项固定为低、中、高、极高、最高，编码沿用 Pi 的 `low/medium/high/xhigh/max`；仅显示模型支持的子集。原始 Pi 事实和映射保留 `off/minimal`，二者不进入产品选项。每模型用户设置可显式调整支持集合，Adapter 使用 Pi 既有编码。模型设置经 ConfigCenter 单模型串行命令保存/恢复默认；目录刷新与重新勾选模型不覆盖用户设置。运行、工具可见性、压缩、UI 读取同一有效配置，每次 run 冻结。
- 详细设计见手册 6A；冻结决策见 `adr/0004-pi-only-model-facts.md` 与 `adr/0005-model-protocol-adapter.md`。
- 添加模型服务优先提供直接的自定义服务入口；官方模板按品牌/平台分组后选择具体区域、套餐、Coding 或云服务方案。每个已保存连接独立持有身份、模型、配置与凭据，同方案允许多个连接，不向用户暴露 `Pi Provider`。原生 provider、鉴权、模型过滤与目录刷新由 Pi Adapter 复用 Pi，ConfigCenter 持有配置和每连接秘密；取消、删除或替换登录后旧请求不能回写凭据。图标不是支持证据，不创建平行协议/登录引擎，不自动合并、迁移或删除已有连接（ADR 0008）。
- 模型交互登录由宿主唯一创建的 `ModelProviderAuthApplication` 经产品鉴权 port 编排，Route 不创建登录服务，Pi 装配与凭据解释留在 Host adapter。凭据写入在全部异步身份检查后同步确认取消，再进入不可取消的发布区；已进入发布区的迟到取消等待真实终态。失败按结构化类别脱敏诊断；缺失的单条服务模板明确警告，不破坏已有连接或自定义入口。工具成本格式由实际冻结模型而非 `native` 连接标签决定（ADR 0009）。
- 自定义模型自动匹配与高级能力设置见 ADR 0010 / 0011；自动匹配不是连接级服务身份，不能触发凭据替换或将混合厂商网关归为一个厂商。高级设置显示有效数值，原样保存不固化目录默认值；恢复默认移除用户设置。

## 3. 应用命令基线

跨 Feature 行为只有以下入口：

```text
attachWorkspaceToSpace
detachWorkspaceFromSpace
reconnectWorkspace
hideWorkspace
deleteWorkspace
deleteSpace
detachKnowledgeFromSpace
```

记忆相关的唯一公开入口：

```text
MemoryAdminApplication.setEnabled / setRollout / clearMemory / updateMemory / getStatus / getMemoryView
MemoryFeature.queries.getDiagnosticSnapshot / searchDiagnosticHistory
CollaborationRulesApplication.get / write / delete / startupSnapshot
```

Panel Route 只能解析输入、调用其中一个入口并映射错误；不得在 Route 或 UI 中组合文件、SQLite、admission 或删除步骤。

Agent 的 `CollaborationRulesRead` / `CollaborationRulesUpdate` 是上述规则 Application 的工具适配，不另建业务入口。

命令语义：

- attach 复用相同 source identity 的 Workspace；新建 implicit Workspace 后若 membership 写入失败，且对象没有引用，则补偿清理登记。Workspace 不再拥有 Conversation。
- detach 只移除 Space membership，不删除 Workspace 或真实目录。
- reconnect 必须验证相同 source identity，并与所有 active Workspace 根执行重复/父子嵌套检查。
- hide 只修改内部 visibility；永久 delete 是资源生命周期操作，删除软件登记、Workspace 规则和引用关系但永不删除真实目录。Workspace 不再触发 Conversation 或 Memory owner 清理。
- delete Space 清理 Space-owned 数据并解除 Knowledge 来源/组织关系；Knowledge-owned 内容保留。

## 4. 身份、授权和并发不变量

- local file 和 Workspace mount 在每次 I/O 前验证当前来源身份。
- 需要 owner admission 的引用/生命周期 mutation 顺序固定为：owner admission -> 解析并获得路径锁 -> 重新读取 membership -> 重新解析 source identity/mountVersion -> 授权 -> I/O。Run 冻结授权下的普通文件工具不额外取得 owner admission，仍在路径锁内重验授权和当前来源。任何入口都不得先持有路径锁再等待 owner admission。
- unlink/delete 与文件 mutation 使用同一锁域；锁外保存的 DTO 不构成授权。
- 首次注册、ensure、reconnect、startup validation 共用同一 Workspace mount policy。
- catch 只能处理声明过的错误 code；Repository、Feature released 和未知错误必须继续上抛。
- Feature 内 read-modify-write 经过唯一串行入口；跨 Feature command 经过协调层串行入口。
- Memory 的 Recall 是可选贡献：Recall deadline 或 Memory-owned index 故障只能在 Host optional adapter 边界变成空贡献；共享 Product Home/SQLite 完整性错误必须继续上抛。
- `data/memory` 的文件快照与备份必须共享 Product Home mutation lock；SQLite backup 依赖 SQLite 的一致性快照和事务边界。不得在持有共享存储锁时等待 per-record/per-owner 队列，避免反向等待。
- PanelHost 在打开任何 Product Home 存储前必须取得 OS-owned runtime lease；同一 Product Home 的第二个进程明确失败。
- Desktop 使用 Electron single-instance lock，并把二次启动聚焦到已有窗口；Panel API 拒绝非 loopback host。

## 5. 数据基线

当前未发布 v1 的目标数据格式为 `synech/v1`，决策见 `adr/0006-unreleased-v1-data-baseline.md`：

- 每个 Repository owner 只维护一个完整的 version 1 目标定义；fresh Product Home 的 schema fingerprint 和 migration ledger 必须等于 `docs/architecture/data-baseline.json`。
- 项目未发布，schema/data format 只维护 `synech/v1` 当前目标，不为开发改动递增 schema、数据格式或产品版本，不追加迁移链，也不兼容旧开发数据；正式发布前另行冻结用户数据迁移政策。
- `synech/v1-baseline-5`、`synech/v1-dev`、未知 namespace、旧 owner 版本或不匹配 checksum 一律明确拒绝。不存在自动升级入口；启动不得静默删除、重建、降级或改写身份与 ledger。经用户明确授权后，只使用 data-only reset 清理本项目产品数据及关联生命周期状态；该操作取得 Product Home lease 并保留 config/凭据、外部 Workspace 文件和共享工作树。
- research owner 保留已退役功能的最终表结构，仅以 version 1 定义新建库，不提供研究读写入口。本次合并不改变表、列、约束和索引；SQL 原文变化导致的 fingerprint 变化必须如实更新。
- 数据格式、owner、schema 或删除语义变化必须先写 ADR，并在同一变更中更新本文和数据基线，说明旧开发库拒绝与恢复影响。
- Repository 读取磁盘/SQLite 后必须执行运行时 schema 校验，不能用 TypeScript `as` 代替。
- Backup manifest v3 覆盖 `knowledge-assets`、`space-files` 和 `memory-data` 三个 durable root；v2 及更早 manifest 或与当前 schema fingerprint/ledger 不匹配的备份必须明确拒绝。manifest 版本独立于 owner schema，Pi 原生 JSONL V4 也不受此数据基线调整影响。

## 6. 显示与错误基线

- Workbench 默认使用目录与单内容区；协作入口仅位于已打开预览的路径/工具栏，由用户显式开启，普通导航、提交和恢复不得自动开启。全局导航与文件目录分别控制，选中文件只切换阅读，不得隐式收起任一导航；打开协作时收起全局导航以让出阅读宽度，文件目录收放保持不变，结束协作回到阅读也不自动展开全局导航。浏览选择与活动 Conversation 独立，但右侧会话面板只投影当前所选 Space 的会话；切换 owner 时不得显示前一 owner 的正文、运行状态或历史条目。分栏、目录收放和浏览导航不得改写 Conversation owner 或隐式扩大上下文授权。
- 单栏由普通布局占满内容区，隐藏面板脱离文档流；分栏实例只在协作时拥有尺寸，退出时同步释放。动画只负责呈现，不持有第二份布局模式或异步提交权。预览工具栏铺满当前面板，正文阅读限宽只作用于正文。
- code、kind、eventType、sectionId、refs 和状态机负责程序分支。
- title、label、message、detail、summary 只负责展示；不得通过字符串比较、正则或本地化文案恢复业务语义。
- UI 乐观状态必须能被权威 HTTP snapshot 覆盖；SSE 只负责失效和增量观察。
- 未知错误如实保留 cause；不得伪装成空状态或静默省略上下文。

## 7. 变更等级

| 变更 | 要求 |
| --- | --- |
| Feature 内实现，不改变契约 | 相关类型检查、构建或人工验证 |
| 跨 Feature command、状态转换、不变量 | 更新基线/Handbook；按风险补充最小验证 |
| owner、公共 API、数据格式、删除语义 | 基线更新、明确迁移/恢复语义，并做最小必要验证 |
| 新运行时或替换 Ordinary/Tool Center | 单独产品决策，不得顺手实施；Agent Runtime Provider 的接入必须遵守 Agent 运行层手册与 ADR 0003 |

## 8. Definition of Done

一个变更只有同时满足以下条件才完成：

1. owner、唯一写入口、关系身份和失败语义明确；
2. 正常、失败、重试、并发、恢复路径复用同一政策函数；
3. 外部输入在 owner 边界解析为结构事实；
4. 数据、API、UI 投影和文档没有第二事实源；
5. 高风险数据、权限、删除、并发或发布变更有针对真实不变量的最小验证；其他改动不默认新增测试；
6. `pnpm check:baseline`、相关 Panel typecheck/build 和 diff check 通过；
7. 当前逻辑切片不混入无关 dirty files。
